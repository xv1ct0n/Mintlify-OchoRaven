# Project 1 — Build an IOC Normalizer

This project teaches foundational Python by building a tool that solves a real defensive-cyber problem: converting a messy list of indicators of compromise (IOCs) into clean, classified, deduplicated, machine-readable data.

<Info>
**Final capability:** You will build `ioc_normalizer.py`, a command-line program that reads a text file, cleans each line, identifies IPv4 addresses, URLs, domains, MD5/SHA-1/SHA-256 hashes, rejects unsupported values, removes duplicates, and exports JSON.
</Info>

## Why this matters

Security analysts regularly receive indicators from reports, tickets, threat-intelligence feeds, incident notes, and partner organizations. The data may contain blank lines, duplicates, inconsistent capitalization, surrounding whitespace, or multiple indicator types. Before indicators can be searched, enriched, shared, or loaded into another defensive tool, they often need to be normalized.

This project intentionally uses the Python standard library so you can focus on core language concepts rather than frameworks.

## Learning objectives

By the end of the project, you should be able to explain and use:

- variables and strings;
- lists, dictionaries, and sets;
- functions, parameters, and return values;
- `if`/`elif`/`else` decisions;
- `for` loops;
- imports and standard-library modules;
- file reading and writing;
- `pathlib.Path`;
- exception handling;
- command-line arguments with `argparse`;
- IPv4 validation with `ipaddress`;
- URL parsing with `urllib.parse`;
- regular expressions with `re`;
- JSON serialization;
- normalization versus validation;
- basic program decomposition.

# Lesson 3 — Read a file

**Free concept walkthrough:** [Python pathlib](https://docs.python.org/3/library/pathlib.html)

## Concept: functions

A function packages a specific behavior. It can receive values as parameters and return a result.

Add this import and function:

```python
from pathlib import Path


def read_indicators(file_path: Path) -> list[str]:
    """Read candidate indicators from a UTF-8 text file."""
    with file_path.open("r", encoding="utf-8") as file:
        return file.readlines()
```

### What each part means

`from pathlib import Path` imports Python's path abstraction. A `Path` object is preferable to manually concatenating filesystem strings.

`file_path: Path` is a type hint. It communicates that the function expects a `Path` object.

`-> list[str]` communicates that the function returns a list of strings.

`with ... as file` uses a context manager. Python closes the file automatically when the block finishes, including when many errors occur.

`readlines()` returns the lines as a list. Newline characters may still be attached; we will clean them next.

# Lesson 4 — Normalize text

**Free concept walkthrough:** [W3Schools strings](https://www.w3schools.com/python/python_strings.asp)

## Concept: strings are values you can transform

Normalization makes equivalent representations consistent. It should be deliberate: changing evidence unnecessarily can destroy meaning.

For our beginner tool we will first perform conservative cleanup:

```python
def clean_value(value: str) -> str:
    """Remove surrounding whitespace from a candidate indicator."""
    return value.strip()
```

`strip()` removes whitespace from the beginning and end of a string. It does not remove spaces inside the value.

Try:

```python
print(repr(clean_value("  198.51.100.25  \n")))
```

Expected:

```text
'198.51.100.25'
```

## Why use `repr()` while learning?

`print()` can hide whitespace. `repr()` displays a representation that makes characters such as `\n` easier to see.

## Blank lines

A blank line becomes an empty string after `.strip()`.

```python
value = clean_value("   \n")

if not value:
    print("Blank value")
```

An empty string is *falsy* in Python, so `if not value:` is a common way to detect it.

# Lesson 5 — Recognize IPv4 addresses

**Free concept walkthrough:** [Python ipaddress](https://docs.python.org/3/library/ipaddress.html)

## Concept: prefer standard-library validators

Do not write complex IP-address validation yourself when Python already provides `ipaddress`.

Add:

```python
import ipaddress
```

Then:

```python
def is_ipv4(value: str) -> bool:
    """Return True when value is a valid IPv4 address."""
    try:
        ipaddress.IPv4Address(value)
        return True
    except ipaddress.AddressValueError:
        return False
```

## Exception handling

Some functions signal invalid input by raising an exception. `try` executes code that might fail; `except` handles an expected failure.

Test:

```python
print(is_ipv4("192.0.2.10"))
print(is_ipv4("999.10.10.10"))
print(is_ipv4("example.com"))
```

Expected:

```text
True
False
False
```

<Info>
Catching the specific `AddressValueError` is better than using a broad `except:` because it avoids silently hiding unrelated programming errors.
</Info>

# Lesson 6 — Recognize cryptographic hashes

**Free concept walkthrough:** [Python hashlib](https://docs.python.org/3/library/hashlib.html)

## Concept: patterns and regular expressions

Common hash values can be represented as hexadecimal strings. For this exercise:

- MD5 = 32 hexadecimal characters
- SHA-1 = 40 hexadecimal characters
- SHA-256 = 64 hexadecimal characters

Import `re`:

```python
import re
```

Create a helper:

```python
def is_hex(value: str) -> bool:
    """Return True when value contains only hexadecimal characters."""
    return re.fullmatch(r"[0-9a-fA-F]+", value) is not None
```

`re.fullmatch()` requires the entire string to match the pattern.

Now classify by length:

```python
def classify_hash(value: str) -> str | None:
    """Return the recognized hash type or None."""
    if not is_hex(value):
        return None

    if len(value) == 32:
        return "md5"
    elif len(value) == 40:
        return "sha1"
    elif len(value) == 64:
        return "sha256"

    return None
```

## Concept: `None`

`None` represents the absence of a value. Here it means, "this string is not one of the hash formats we support."

Test valid and invalid examples before continuing.

# Lesson 7 — Recognize URLs

**Free concept walkthrough:** [Python URL parsing](https://docs.python.org/3/library/urllib.parse.html)

Use Python's URL parser:

```python
from urllib.parse import urlparse
```

```python
def is_url(value: str) -> bool:
    """Return True for HTTP or HTTPS URLs containing a hostname."""
    parsed = urlparse(value)
    return parsed.scheme in {"http", "https"} and bool(parsed.hostname)
```

## Concept: sets

`{"http", "https"}` is a set. Membership tests such as `x in my_set` are concise and efficient.

The function requires both a supported scheme and a hostname. That prevents many arbitrary strings from being treated as URLs.

Test:

```python

print(is_url("hello"))
```

# Lesson 8 — Recognize domains

**Free concept walkthrough:** [W3Schools strings](https://www.w3schools.com/python/python_strings.asp)

Domain validation can become complicated. For this beginner project, use a deliberately limited rule suitable for learning rather than pretending to implement every valid DNS name.

```python
DOMAIN_PATTERN = re.compile(
    r"^(?=.{1,253}$)(?:[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?\.)+[A-Za-z]{2,63}$"
)


def is_domain(value: str) -> bool:
    """Return True when value matches the project's simplified domain rule."""
    return DOMAIN_PATTERN.fullmatch(value) is not None
```

### Read the pattern conceptually

You do not need to memorize it. Understand the intent:

- the complete value must match;
- labels are separated by dots;
- labels may contain letters, numbers, and internal hyphens;
- the final label uses letters;
- total and label lengths are bounded.

<Warning>
Real-world internationalized domains, unusual valid DNS labels, defanged indicators, IPv6, email addresses, and other observable types require additional handling. Documenting what your tool does **not** support is part of good engineering.
</Warning>

# Lesson 9 — Build one classifier

**Free concept walkthrough:** [W3Schools strings](https://www.w3schools.com/python/python_strings.asp)

You now have specialized validators. Combine them behind one function.

```python
def classify_indicator(value: str) -> str | None:
    """Classify a supported IOC value."""
    if is_ipv4(value):
        return "ipv4"

    if is_url(value):
        return "url"

    hash_type = classify_hash(value)
    if hash_type:
        return hash_type

    if is_domain(value):
        return "domain"

    return None
```

## Why order matters

Classification rules can overlap. A central function gives you one explicit place to control precedence. As your tool evolves, you can test ambiguous cases rather than scattering classification logic throughout the program.

# Lesson 10 — Type-specific normalization

**Free concept walkthrough:** [W3Schools strings](https://www.w3schools.com/python/python_strings.asp)

Lowercasing everything is tempting but not always correct. Normalize based on the indicator type.

For this project:

- IPv4: canonicalize with `ipaddress`;
- domains: lowercase;
- hashes: lowercase;
- URLs: preserve the complete original URL after trimming.

```python
def normalize_indicator(value: str, indicator_type: str) -> str:
    """Normalize a validated indicator according to its type."""
    if indicator_type == "ipv4":
        return str(ipaddress.IPv4Address(value))

    if indicator_type in {"domain", "md5", "sha1", "sha256"}:
        return value.lower()

    return value
```

This distinction is important: **cleaning**, **validation**, **classification**, and **normalization** are related but separate operations.

# Lesson 12 — Process every line

**Free concept walkthrough:** [Python tutorial](https://docs.python.org/3/tutorial/)

Now combine the pieces.

```python
def process_indicators(lines: list[str], source: str) -> tuple[list[dict], list[str]]:
    """Clean, classify, normalize, and deduplicate candidate indicators."""
    records = []
    rejected = []
    seen = set()

    for line in lines:
        value = clean_value(line)

        if not value:
            continue

        indicator_type = classify_indicator(value)

        if indicator_type is None:
            rejected.append(value)
            continue

        normalized = normalize_indicator(value, indicator_type)
        dedupe_key = (indicator_type, normalized)

        if dedupe_key in seen:
            continue

        seen.add(dedupe_key)
        records.append(make_record(normalized, indicator_type, source))

    return records, rejected
```

## What is happening?

`records = []` creates the list of accepted structured indicators.

`rejected = []` keeps unsupported values visible instead of silently discarding them.

`seen = set()` creates a set for deduplication.

`for line in lines:` processes each candidate.

`continue` skips the remainder of the current loop iteration and moves to the next line.

`dedupe_key = (indicator_type, normalized)` creates a tuple. A tuple can be stored in a set, giving us a convenient unique key.

### Why deduplicate after normalization?

`EXAMPLE.COM` and `example.com` should become one domain record. If you deduplicated before normalization, they would appear different.

# Lesson 15 — Handle expected errors

**Free concept walkthrough:** [Python exceptions](https://docs.python.org/3/tutorial/errors.html)

Analyst tools should fail clearly when the user makes a recoverable mistake.

Create the orchestration function:

```python
def main() -> int:
    args = parse_args()

    if not args.input.exists():
        print(f"Error: input file does not exist: {args.input}")
        return 1

    if not args.input.is_file():
        print(f"Error: input path is not a file: {args.input}")
        return 1

    try:
        lines = read_indicators(args.input)
        records, rejected = process_indicators(lines, args.input.name)
        write_json(records, args.output)
    except (OSError, UnicodeError) as exc:
        print(f"Error: {exc}")
        return 1

    print(f"Accepted indicators: {len(records)}")
    print(f"Rejected values: {len(rejected)}")
    print(f"Output: {args.output}")

    if rejected:
        print("\nRejected values:")
        for value in rejected:
            print(f"  - {value}")

    return 0
```

Then add the standard entry point:

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

## Why this pattern?

Importing a Python file and executing a Python file are different use cases. The `__name__` guard prevents `main()` from automatically running when the module is imported by another Python program or future test suite.

Returning `0` represents success. A non-zero exit status represents failure and becomes especially useful later in shell scripts and CI/CD pipelines.

| Test | Expected behavior |
| --- | --- |
| Blank line | ignored |

## Debugging exercise

If a value is classified incorrectly, trace the pipeline in order:

```text
What did read_indicators() return?
        ↓
What did clean_value() produce?
        ↓
Which validator returned True?
        ↓
What did normalize_indicator() change?
        ↓
Was the dedupe key already in seen?
```

This method is more valuable than randomly editing code until the symptom disappears.

# Completion criteria

You have completed Project 1 when you can rebuild the major pieces without copying the final solution and can explain **why** each component exists.

Your finished tool should:

- accept an input path from the command line;
- safely read a text file;
- remove blank lines and surrounding whitespace;
- identify supported IPv4, domain, URL, MD5, SHA-1, and SHA-256 values;
- normalize values according to type;
- reject unsupported values without crashing;
- deduplicate after normalization;
- preserve source information;
- create output directories as needed;
- export valid JSON;
- return a useful process exit status;
- provide command-line help;
- include a README documenting usage and limitations.
