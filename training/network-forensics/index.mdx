# Network Forensics learning path

Network forensics turns packet captures and network telemetry into evidence you can use to answer investigative questions. This course starts with Wireshark fundamentals and progressively moves into protocol analysis, behavioral investigation, artifact handling, and correlation across defensive tooling.

<Info>
**Audience:** Beginner through advanced cybersecurity practitioners. Beginners should understand basic IPv4 addressing and the purpose of TCP, UDP, and DNS. More experienced analysts can move quickly through the foundations and focus on the advanced exercises.

**Outcome:** Complete the path and you should be able to scope a PCAP investigation, reconstruct network conversations, investigate DNS and web activity, identify periodic or suspicious communication patterns, extract artifacts safely, correlate packet evidence with Security Onion/Arkime/Suricata telemetry, and produce a defensible investigation report.
</Info>

## Course progression

<Steps>
  <Step title="Lab 1 — Packet Analysis Foundations">
    Learn the Wireshark interface, packet anatomy, capture scope, endpoints, conversations, capture versus display filters, and a repeatable triage workflow.
  </Step>
  <Step title="Lab 2 — DNS Investigation">
    Reconstruct DNS activity, distinguish queries from responses, analyze record types and failures, and pivot from names to subsequent network connections.
  </Step>
  <Step title="Lab 3 — HTTP, TLS, and Web Traffic">
    Analyze HTTP transactions and encrypted web metadata, reconstruct streams, inspect TLS handshakes, and understand what encryption does and does not hide.
  </Step>
  <Step title="Lab 4 — Beaconing and C2-Like Patterns">
    Use benign synthetic traffic to investigate periodic connections, timing, destination consistency, and packet-size patterns without treating periodicity alone as proof of compromise.
  </Step>
  <Step title="Lab 5 — File and Artifact Analysis">
    Identify network-delivered objects, export authorized training artifacts, calculate hashes, document provenance, and connect packet evidence to YARA and IOC workflows.
  </Step>
  <Step title="Lab 6 — Security Onion and Arkime Correlation">
    Start from alerts or indexed session telemetry, narrow the time/host/session scope, retrieve relevant PCAP, and validate conclusions at packet level.
  </Step>
  <Step title="Lab 7 — Capstone Investigation">
    Conduct an end-to-end investigation with minimal guidance and produce a concise evidence-based report separating observations, interpretations, and limitations.
  </Step>
</Steps>

## Tool and language boundaries

| Tool | Primary role in this path | Query/filter language |
| --- | --- | --- |
| Wireshark | Interactive packet dissection | Wireshark display filters |
| TShark | Repeatable CLI packet analysis | Wireshark display filters with `-Y` |
| Arkime | Indexed session search + PCAP | Arkime search expressions |
| Suricata | IDS/IPS + protocol/event telemetry | Suricata rule syntax; EVE JSON output |
| Security Onion | Integrated alert/hunt/session/PCAP workflow | Interface depends on data and deployed version |
| Elasticsearch/Kibana | Indexed event search and correlation | KQL, Lucene, ES|QL, or APIs depending on workflow/version |
| OpenSearch | Indexed event search and analytics | OpenSearch query mechanisms/PPL depending on deployment |
| YARA | File/content classification | YARA rules |

<Warning>
Do not copy a query literally between platforms. Translate the investigative question and identify the fields available in each data source.
</Warning>

## Completion standard

You are ready to move beyond this path when you can receive an IP, hostname, timestamp, IDS alert, or suspicious session and independently determine:

1. what traffic is actually present;
2. which conversations are relevant;
3. what the packet evidence directly establishes;
4. what conclusions require additional telemetry;
5. which artifacts and pivots should be preserved;
6. how to reproduce your analysis with filters or TShark; and
7. how to communicate findings without overstating the evidence.
