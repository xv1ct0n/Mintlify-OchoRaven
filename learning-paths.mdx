# Cybersecurity learning paths

Choose a starting stage, build evidence of skill in a lab, and then select a specialization. You can combine paths. The sequence matters more than a calendar deadline.

## Choose your starting point

| Stage | Start with | Demonstrate progress |
| --- | --- | --- |
| Beginner | [Operating systems](/domains/operating-systems), [network security](/domains/network-security), [free platforms](/free/platforms), [entry-level certifications](/certifications/entry-level) | Explain a DNS lookup and TCP session, use Linux and PowerShell basics, and complete guided labs. |
| Intermediate | [SIEM and tools](/domains/siem-and-tools), [blue team and SOC](/domains/blue-team-and-soc), [Python](/training/python/index), [intermediate certifications](/certifications/intermediate) | Investigate a sample dataset, produce a timeline, and build one tested automation utility. |
| Advanced | Pick a domain path below, use [advanced certifications](/certifications/advanced) where relevant, and build a portfolio of defensible analysis | Design and validate a detection, investigation, architecture, or tool that another analyst can reproduce. |

## Suggested sequences

### Blue team and detection engineering

1. [Linux and Windows foundations](/domains/operating-systems) → [network traffic analysis](/domains/network-security).
2. [SIEM and tools](/domains/siem-and-tools) → [blue team and SOC](/domains/blue-team-and-soc).
3. [Python beginner projects](/training/python/beginner) → [DCO and detection engineering projects](/training/python/dco-detection-engineering).
4. Build a portfolio entry with sample data, query or rule, test cases, false positives, and an analyst-facing explanation.

### DFIR and malware

1. [Network security](/domains/network-security) → [SIEM investigation](/domains/siem-and-tools).
2. [Malware analysis](/domains/malware-analysis) → [CTF and forensics challenges](/free/ctf-and-labs).
3. Document a case timeline, evidence sources, indicators, confidence, and containment recommendations.

### OT security

1. [Network security](/domains/network-security) → [ICS and OT security](/domains/ot-security).
2. Use lab traffic to document device roles and normal protocol behavior.
3. Develop a detection hypothesis, validate it safely, and explain operational impact.

### Leadership and architecture

1. Build depth in [cloud security](/domains/cloud-security), [security operations](/domains/blue-team-and-soc), and risk-based decisions.
2. Follow the [CISSP study path](/training/cissp/index) and map work to the [official exam outline](https://www.isc2.org/certifications/cissp/cissp-certification-exam-outline).
3. Practice explaining tradeoffs, ownership, and business impact alongside technical controls.

<Note>
  Use [hands-on labs](/practice/home-labs) and [CTFs](/practice/capture-the-flag) throughout. Work only on systems and data you are authorized to use.
</Note>
